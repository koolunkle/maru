# 데모 데이터 만드는 법

`tasks.md` 1절(데이터 준비)을 실행하는 순서다. 운영 DB에 바로 쓰므로 관리자가 한다. 리허설 전에 한 번, **시연 전날 한 번 더** 실행한다. 연속 출석은 하루라도 비면 끊기기 때문에, 시연 전날 다시 실행해야 "어제까지 7일"이 시연 날까지 이어진다.

| 계정 | 쓰는 곳 | 준비 |
| --- | --- | --- |
| 민수 (7일 기록) | 출석·난이도·가구·성장 화분·주간 리포트·"2번 더 하면 운동화 선반" | 시연 브라우저에서 온보딩(산책·운동, 관악구, 30분 이상) → `demo-history.sql` |
| 지은 (새 계정) | 온보딩부터 동네 행사 주간 미션까지 그 자리에서 진행 | 준비 없음. 구는 종로구(시연일 행사 36개, 11/2 확인) |
| 보조 | 민수가 받는 우체통 글, 미션 상세의 "먼저 해낸 사람의 한 줄" | `demo-helper.mjs` |

## 1. 민수 계정 (tasks 1.1)

1. 시연에 쓸 브라우저로 운영 URL을 열고 온보딩한다. 관심사에 **산책·운동**을 넣고 구는 **관악구**(발표 페르소나)로 고른다. 다른 브라우저나 시크릿 창으로 만들면 시연 때 그 계정으로 들어갈 수 없다(익명 로그인).
2. 설정 화면의 닉네임으로 사용자 id를 찾는다.
   ```sql
   select id, onboarded_at from public.profiles where nickname = '느긋한 고양이' order by onboarded_at desc;
   ```
3. 사진 7장을 `verifications` 버킷의 `<사용자 id>/demo-1.jpg` ~ `demo-7.jpg`로 올린다. 직접 찍은 사진만 쓰고 얼굴·번호판·저작권 있는 이미지는 피한다. 인증은 모두 비공개로 저장되어 피드에는 나오지 않는다.

   | 번호 | 미션 | 사진 |
   | --- | --- | --- |
   | 1 | 길에서 노란색 찾아 찍기 | 노란색이 보이는 풍경이나 사물 |
   | 2 | 오늘 먹은 집밥 기록하기 | 밥 |
   | 3 | 장바구니나 텀블러 챙겨 나가기 | 장바구니나 텀블러 |
   | 4 | 좋아하는 책 한 구절 옮겨 적기 | 손으로 옮겨 적은 문장 |
   | 5 | 반려식물이나 반려동물 사진 남기기 | 반려식물이나 반려동물 |
   | 6 | 동네 걸으며 쓰레기 줍기 | 주운 쓰레기 봉투 |
   | 7 | 길에서 노란색 찾아 찍기 | 1번과 다른 노란색 사진 |

   ```bash
   # 사진 폴더에서 실행한다(Windows에서는 C:/ 경로를 그대로 넘기면 CLI가 잘못 읽는다)
   for i in 1 2 3 4 5 6 7; do
     npx --prefix <저장소> supabase storage cp demo-$i.jpg ss:///verifications/<사용자 id>/demo-$i.jpg \
       --workdir <저장소> --linked --experimental --content-type image/jpeg
   done
   ```
4. `demo-history.sql`의 `demo_user`에 사용자 id를 넣고 SQL Editor에서 실행한다. 다시 실행하면 그 계정의 미션·인증·기록·가구를 지우고 실행한 날 기준으로 다시 만든다(프로필과 사진은 남긴다).

결과(실행일 D 기준): D-7 ~ D-1에 미션 7개 완료(산책 3회), 연속 출석 7일, 난이도 1 → 3, 가구 화분·스탠드·소파(배치는 시연에서), 기분 1~3과 한 줄 기록 7일. 11/2에 임시 계정으로 두 번 실행해 같은 결과가 나오는 것을 확인하고 지웠다.

## 2. 보조 계정 (tasks 1.2, 1.3)

시연 전날, 민수 계정을 다시 만든 뒤 실행한다. 우체통 글은 먼저 우체통을 연 사람이 받아 가므로, 실행한 뒤 **바로 민수 브라우저에서 마음 보관함 탭 → 우체통을 열어** 받아 둔다.

```bash
node --env-file=.env.local openspec/changes/prepare-demo-rehearsal/demo-helper.mjs <노란색 사진.jpg>
```

익명 계정 생성 → 온보딩 → "길에서 노란색 찾아 찍기" 시작 → 사진 인증(실제 AI 판정) → 릴레이 한 줄 → 우체통 글 순서로 앱과 같은 경로를 탄다. 검수도 실제 서버 함수가 한다. 출력되는 보조 계정 id를 정리(tasks 3.3)까지 적어 둔다.

- 인증이 통과하지 않으면 거기서 멈춘다. 노란색이 잘 보이는 사진으로 다시 실행한다(새 보조 계정이 생기므로 앞 계정도 정리 대상).
- 릴레이는 승인 뒤 3시간(시연 모드면 1분) 뒤에 공개된다. 시연 전날 실행하면 시연 때는 공개되어 있다.
- 11/2에 앞부분(계정·온보딩·미션 시작·사진·AI 판정)을 임시 계정으로 확인했다. 앱 아이콘 이미지는 "직접 찍은 사진이 아니"라고 판정되어 릴레이·우체통 전에 멈췄고, 임시 계정과 사진은 지웠다.

## 3. 정리 (tasks 3.3)

보조·임시 계정은 id로만 지운다. 시간 범위나 조건으로 한꺼번에 지우지 않는다(다른 사람 계정이 섞일 수 있다). Storage 사진을 먼저 지우고 계정을 지운다.

```sql
select name from storage.objects where bucket_id = 'verifications' and name like '<사용자 id>/%';
```

```bash
npx supabase storage rm ss:///verifications/<위에서 나온 경로> --linked --experimental --yes
```

```sql
delete from auth.users where id = '<사용자 id>';
```
