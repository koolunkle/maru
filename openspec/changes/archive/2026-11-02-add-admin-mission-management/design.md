## 접근 권한

사용자는 외부 웹과 공유 관리자 비밀번호를 선택했다. /admin은 앱의 익명 온보딩과 분리해 직접 접근한다. 비밀번호는 서버 시크릿 ADMIN_PASSWORD에만 두며 화면의 React 메모리에서만 입력값을 유지한다. 이메일 계정이나 관리자 계정을 만들지 않는다. 모든 관리 요청을 admin-missions 함수에서 검사하고 HTTPS 요청 본문으로만 비밀번호를 전송한다. 서버의 고정 길이 해시를 비교하며 비밀번호 자체는 로그·URL·저장소에 남기지 않는다.

입력 시도는 서버 전용 테이블과 원자적 RPC로 제한한다. 프록시가 제공한 원격 주소는 서버 시크릿과 함께 해시해서 저장하고 값이 없으면 공통 제한 키를 쓴다. 주소별 틀린 입력 5회 후 10분 제한하며 주소 헤더 변경을 통한 우회를 막도록 전체 틀린 입력도 10분당 100회로 제한한다. JWT 검증 대신 이 함수 자체의 비밀번호 검사를 사용하며 기존 함수들의 JWT 설정은 유지한다. 관리 응답에는 Cache-Control: no-store를 설정한다.

## 데이터와 저장

관리 대상은 사용자 개인 AI 미션을 제외한 공용 seed/event 미션이다. 새 관리 미션은 source=seed, seed_no 없음으로 등록하고 기존 스키마의 필수 값·길이를 지킨다. 기간은 기존 KST 양 끝 포함 규칙을 따른다. 사용자가 수행한 미션·참여·릴레이 또는 사진이 연결된 미션은 삭제하지 않는다. 삭제와 사진 개수 제한은 서버 전용 RPC가 미션 행 잠금 안에서 검사해 경합을 막는다. 모든 새 테이블은 RLS를 켜고 일반 클라이언트 권한을 회수한다.

사진은 서버에서 2 MiB·매직 바이트·4장 제한을 확인한다. 고유 경로로 먼저 Storage에 저장하고 원자적으로 연결한다. 연결 실패 시 파일을 지우며 정리 실패도 오류로 알린다. 삭제는 파일을 지운 뒤 연결을 제거한다. 파일 삭제 오류 시 원래 연결을 유지하고, 연결 삭제 오류 시 성공으로 표시하지 않고 다시 삭제하도록 안내한다. 파일 삭제 중에도 연결을 유지해 미션 삭제와의 경합을 막는다. 기존 경로를 덮어쓰지 않는다. 서버 전용 읽기 권한을 유지하고 관리자에게만 경로와 짧은 만료의 미리보기 URL을 돌려준다.

## 운영과 검증

관리 함수·마이그레이션은 기존 운영 DB 한 개에 영향을 주므로 검증 후 리뷰 대상과 적용 내역을 명시한다. 미리보기 웹은 기존 프로젝트에 배포한다. 신규 서버 시크릿은 앱 환경 변수로 만들지 않으며 사용자에게 채팅으로 비밀번호를 요구하지 않는다. 운영 공용 데이터는 읽기만 확인하고 변경 검증은 임시 자료를 만들어 수행한 뒤 정리한다.
