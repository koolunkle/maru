## 3. 작업별 범위와 완료 기준

### T1 릴레이 테이블·공개 cron·RPC

- 새 마이그레이션: `relay_messages`(PRD §6.1), RLS(본인 읽기, mission_id·body만 insert), category·status·publish_at을 채우는 트리거(`prepare_comment`와 같은 방식), (mission_id, user_id) 유일 제약.
- `publish_due_comments()`가 `relay_messages`도 공개하도록 수정.
- RPC `get_relay_messages(mission uuid)`: published, 본인 제외, 같은 미션 최신 3개, 부족하면 같은 category 최근 7일로 채움. 본문만 반환.
- 완료: Supabase 보안 점검(advisors)에 새 경고 없음, 타입 재생성(`src/types/database.ts`), SQL로 두 계정 시나리오 확인.
- 구현·검증: `20261027110000_relay_messages.sql`, `supabase/tests/relay.sql`. pass·privacy 완료 인증만 작성, 본인 읽기·필드 단위 insert 권한, 작성자 제외, 같은 미션 우선·같은 카테고리 7일 이내, 공개 시각과 기존 댓글 cron 검증. 사용자 승인으로 운영 DB에 적용 후 운영 스키마에서 DB 타입 재생성.
- 운영 보안 Advisors에 릴레이 관련 경고 2개: 인증 사용자에게 `SECURITY DEFINER` 조회 RPC가 실행 가능하고 익명 로그인 계정에도 본인 행 읽기 정책이 허용된다는 내용. 두 권한 모두 익명 사용자 기능에 필요하며 RPC는 접근 가능한 미션의 공개 본문만, 직접 조회는 `auth.uid()` 본인 행만 반환한다. 다른 사용자 조회·수정 차단은 테스트했다.
- 롤백 시 릴레이 테이블은 보존하고 앱 노출과 릴레이 검수를 중단한 뒤 기존 댓글 전용 cron 함수로 복원한다. 저장된 글을 삭제하지 않는다.

### T2 `moderate-comment`에 relay_id 처리 추가

- 입력 `{ comment_id }` 또는 `{ relay_id }`. 분류 기준과 실패 시 pending 유지는 댓글과 같다.
- 완료: 연락처가 든 한 줄은 `rejected`, 위기 표현은 `crisis`, 일반 응원은 `approved`.
- `npm run test:relay`로 댓글과 릴레이 각각의 검수, 본인 확인, 재호출, 검수 오류 및 상태 변경 오류 확인. 운영 함수 배포 후 실제 AI가 일반 응원을 `approved`, 전화번호 포함 글을 `rejected`로 판정하고 저장한 것을 확인했다.

### T10 마음 우체통 송수신

- 2026-10-27 요청으로 수신함과 실제 전달 서버까지 범위 확장. 홈 카드 → 받은 목록 → 본문·읽음 저장. 보낸 목록·검수 상태·검수 재요청·작성 시트 제공.
- `supabase/migrations/20261027090000_mailbox.sql`: 독립 테이블, 클라이언트 직접 접근 차단, 서버 전용 배정 RPC. 다른 사람의 승인 글만 한 사람에게 배정하며 안 읽은 글이 있으면 추가 배정하지 않는다. 프로필 행 잠금·`SKIP LOCKED`로 동시 배정을 제어한다.
- `supabase/functions/mailbox/index.ts`: JWT 인증, 1~60자 검증, 요청 ID별 중복 방지, AI 검수, 본인 발신·수신 목록, 수신자만 읽음 변경. 작성자·수신자 ID는 응답에 포함하지 않는다. 검수 장애 시 비공개 대기 및 수동 재시도.
- `src/lib/mailbox.ts`에서 서버를 호출한다. 기존 로컬 보관분은 자동 발송하지 않는다. 홈 포커스마다 조회하고 안 읽은 글이 있으면 KST·계정별 하루 한 번 시트를 연다.
- 로컬 검증: 클라이언트·서버 로직 테스트 10개, 전체 SQL 마이그레이션 재현 및 `supabase/tests/mailbox.sql`의 배정·권한·입력·중복 저장 검증 통과. 배포 후 공식 Supabase CLI로 운영 스키마의 DB 타입 재생성. lint·typecheck·웹 export 통과.
- 브라우저 검증: 격리한 테스트 API로 수신 시트 자동 표시, 받은 목록 → 본문 → 읽음·안 읽은 개수 감소, 모바일 폭(390px) 작성·보낸 목록·상태 표시 확인. 운영 데이터는 사용하지 않았다.
- 운영 반영(2026-10-27): 사용자 명시 승인으로 PR 리뷰 전 적용하는 예외를 받아 `20261027090000_mailbox.sql` 및 `mailbox` 함수 배포 완료. 운영 익명 테스트 계정 두 개로 인증·수신 조회·본문·읽음 저장·읽음 재요청의 멱등성·발신자의 읽음 요청 차단(404) 확인 후 테스트 계정과 글 삭제. 승인된 테스트 글은 같은 트랜잭션에서 테스트 수신자에게 배정해 실제 사용자에게 전달하지 않았다.
- 배포 후 보안 Advisors 확인: 우체통 테이블·RPC 관련 경고·오류 없음. 기존 RPC의 SECURITY DEFINER 실행 권한, 기존 테이블의 익명 접근 정책, Auth 비밀번호 보호 설정 관련 경고 20건은 이번 범위에서 변경하지 않았다.
- 미검증: 실제 AI 검수(로컬에서는 모의 결과로 검증), 동시 요청 부하, Expo Go 실기기. SQL 회귀 검증은 운영 DB가 아닌 로컬 DB에서 실행한다. 저장소의 리뷰·병합 절차는 남아 있어 상태는 `리뷰`로 유지한다.

- `20261027120000_daily_notes.sql`: 한국 시간 하루 한 행, 본인만 읽기·작성·수정·삭제, 서버 날짜와 계정을 확인하는 원자적 저장 RPC. AI 전송은 없다. 90일 자동 삭제는 보관 정책 결정 전이라 적용하지 않는다.
- 로컬 검증: `npm run test:daily-note`, `supabase/tests/daily_notes.sql`의 날짜·중복·권한·입력 검증. 격리된 테스트 API로 브라우저에서 선택·저장·재진입·수정·삭제, 선택 상태 접근성과 390px 화면 확인. lint·typecheck·웹 export 통과.
